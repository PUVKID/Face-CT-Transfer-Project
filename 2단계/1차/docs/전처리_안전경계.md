# 전처리 안전 경계와 판정 근거

2단계는 공식 원본 두 조각의 크기·MD5를 상수와 대조한 뒤 읽는다. 이 상수는 현재 내려받은 바이트에서 새 기준을 만들지 않는다. 전체 CT 46조각 다운로드의 완료를 이 결절 블록 분석 완료 조건으로 바꾸지 않으며, 다운로드 프로세스를 수정하거나 종료하지 않는다.

ZIP64·LZMA는 Python 표준 라이브러리가 처리하며 두 조각은 가상 연결 읽기로 읽는다. 원본을 합쳐 6.8GB를 다시 복사하거나 전체 3D 원본을 별도로 추출하지 않는다. archive 경로·중복·CSV ID 전체 일치와 각 파일의 비압축 크기를 검사한다.

객체 metadata NPY는 임의 `np.load(..., allow_pickle=True)`를 사용하지 않는다. 제한한 placeholder dtype·배열만 재구성하고 허용하지 않은 전역 함수와 실행 opcode를 거부한다. 객체 루트의 정확한 세 키·숫자 벡터 형상·유한값·양의 spacing·역행렬을 검증한다. 숫자 volume도 NPY header의 dtype·형상·바이트 상한을 먼저 검사하고, 실제 payload 크기가 같은 경우에만 `frombuffer`로 읽는다. 악성 함수가 파일을 생성하려는 fixture와 큰 배열 header fixture는 실제 검사로 거부한다.

공식 전처리 근거는 [baseline dataloader.py](https://github.com/DIAGNijmegen/luna25-baseline-public/blob/main/dataloader.py)의 `extract_patch`와 `volumeTransform`, [메타데이터 생성](https://github.com/DIAGNijmegen/luna25-baseline-public/blob/main/preprocessing/utils.py)의 `itk_image_to_numpy_image`다. z,y,x 좌표와 블록 중앙을 사용하며 spacing과 행 정규화가 실제 물리 시야에 영향을 준다. 동일 HU 상수 영상만으로는 이 오류를 찾을 수 없어, 2mm 원본의 선형 화소 램프가 10mm/5 출력에서 한 원본 화소 간격으로 이동하는 별도 계약 검사를 둔다.

2D 입력만 만들므로 SimpleITK·nibabel·7zip 추가 설치는 필요하지 않다. 전체 체적을 별도 작업에 쓰려면 해당 작업의 좌표·라벨·원본 CT 안전 경계를 다시 정해야 한다. 결절이 없는 영상과 건강한 정상은 같은 개념이 아니며, 이 전처리는 정상 라벨을 새로 만들지 않는다.

캐시는 실제 원본·전처리 소스·출력 SHA-256에 결합한다. 현재 출력 해시를 과거 검증 기준으로 덮어쓰지 않으며, 불일치는 기존 파일을 보존하고 차단한다. cache·환자/결절 키·특징은 비공개다.
