# 실제 획득 상태와 실행 인계

소스 cwd는 `1단계/2차`, Python은 `1단계/work/venv/Scripts/python.exe`다. 원본은 `1단계/data/face_benchmarks/raw`, 모델은 `1단계/models/topofr`, 파생 캐시는 `data/face_benchmarks/derived`, 비공개 운영·실패 영수증은 `work/stage1_revision2`에 저장한다. 원본 의료 자료와 기존 AdaFace 실행을 수정하거나 재개하지 않는다.

2026-11-03 최초 획득에서 TopoFR1214223369바이트·LFW180566744바이트·pairs155335바이트와 고정 저자 소스를 확보했다. 모델은 공식 길이와 최초 로컬 SHA 고정, LFW/pairs는 공식 SHA 대조, 저자 소스는 공식 Git blob 대조를 구분한다. 이후 공식 설정3개와 YuNet232589바이트를 고정 원출처로 추가했다. IJB는 HTML 응답으로 종료됐고 진단에서 Google Drive quota exceeded를 확인했다. 실패 원문을 보존하며 우회·단기 반복 재시도·완료 표시를 하지 않는다.

실제 검사와 이후 계획은 구분한다. CPU `tools/inspect_model.py`는 초기 생성 인자 누락으로 실패했고, 공식 설정과 원본 체크포인트 형상 확인 뒤 생성 인자를 수리했다. 이후 안전 CPU strict 적재는 성공했다. 얼굴 영상 추론이나 GPU 평가는 이 검사에 포함되지 않는다.

독립 검증 뒤 사용할 명령은 다음과 같다. 준비는 CPU 정렬이며, 평가 명령은 준비 coverage100%가 아니면 차단된다. CLI는 임의 파일 경로나 명령을 받지 않는다.

```powershell
& '../work/venv/Scripts/python.exe' -B -X utf8 tools/run_lfw.py prepare
& '../work/venv/Scripts/python.exe' -B -X utf8 tools/run_lfw.py evaluate --device cuda:0 --batch-size 4
```

첫 prepare 실행은 원본 추출 뒤 OpenCV의 한글 ONNX 파일명 로딩에서 종료1로 실패했으며 원문과 당시 상태를 별도 보존했다. 공식 SHA가 같은 YuNet 바이트를 공식 buffer overload로 전달하도록 수리하며 threshold/NMS/topK·CPU backend·정렬 기준은 유지한다. 모델 생성 검사는 실제 얼굴 detect나 TopoFR 추론이 아니다. 재실행은 새 독립 검증 후 시작하며 기존 추출 파일은 archive 바이트와 비교한 뒤 재사용하고 덮어쓰지 않는다. 평가 명령은 아직 실제 실행 전이다. 공식 API 근거: https://docs.opencv.org/4.13.0/df/d20/classcv_1_1FaceDetectorYN.html

실행 환경에는 `FACE_SESSION_ID`, `FACE_TASK_ID`, `FACE_REPAIR_USED`, `FACE_INPUT_FIX_USED`를 주입하고 실제 argv·cwd·프로세스·시각·종료 코드를 보존한다. 기존 argv 필드는 유지하며 interpreter flags를 포함한 `sys.orig_argv`를 별도 비공개 필드에 기록한다. 공용 API에는 이 운영 식별자나 원문 실패 traceback을 제공하지 않는다. 기존 서버·다른 GPU 프로세스·원천 CT 수집을 종료하지 않는다.

준비 중 실제 추출 바이트·정렬 영상 수·실패 수, 평가 중 영상 수·ETA 추정·GPU 자원을 상태로 저장한다. 특징은 매 batch flush 후 재개 위치를 원자 저장한다. 준비 실패 시 전체 정렬 coverage와 원문을 보존하며 정확도는 null이다. LFW 완료 시만 해당 직접 측정값을 기록하고 IJB 대기는 계속 구분한다. 평가에 epoch·학습 곡선을 생성하지 않는다.

두 번째 prepare는 실제 정렬 도중 상태 JSON 원자 교체의 WinError5로 종료1이었으며 전체 coverage는 미완료다. 실제 점유 주체는 확정하지 않았다. 원자 저장은 UTF-8 전체 JSON을 임시파일에 쓰고 fsync한 뒤 교체하며 Windows PermissionError의 winerror5/32/33에만 최대8회, 50ms 간격, 0.75초 재시도 창을 적용한다. OS 호출·스케줄링 지연까지 절대 소요시간을 보장하는 값은 아니다. 성공할 때만 반환하고 지속 점유·다른 오류는 원문 예외를 전파하며 기존 대상이나 실패 임시파일을 삭제하지 않는다. 실제 Windows 읽기 핸들 해제 후 회복과 영구 점유 실패를 제어 검사한다. 보존한 불완전 정렬 배열은 완료·재개 근거로 사용하지 않고 다음 준비에서 원본을 재검증한 뒤 전 영상을 새로 정렬한다. 파일 공유·이동 근거: https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilea , https://learn.microsoft.com/en-us/windows/win32/fileio/moving-and-replacing-files

기법 카드는 실제 추출·정렬·추론·6000쌍 계산 단계와 함께 갱신한다. 추출을 정렬 적용으로 표시하지 않으며 정렬 조건 미충족은 coverage를 보존한 일시중단이다. 도달하지 않은 FP32·반전·LFW는 미적용이고, 실패한 적용 중 기법은 실패로 종료한다. 검증된 정렬/특징 캐시 재사용과 이번 작업의 신규 추론 유무를 구분한다. IJB-C template 집계와 CT 학습은 이 LFW 작업에서 미사용이다. 이 상태 전환 회귀의 제어 결과를 실제 얼굴 정확도로 기록하지 않는다.

중앙 회귀 명령은 `python -B -X utf8 -m unittest discover -s tests -v`이며 실제 고정 venv를 사용한다. 검사 수와 결과는 실행별 비공개 영수증으로 보존하며 과거 13·18·19개 검사 기록을 최신 검사로 바꿔 쓰지 않는다. 완료·공개 판단은 별도 독립 검증과 공개 gate에 따른다.

독립 검토의 private tar fixture에서 `x.extract.part`와 `x`가 고정 임시 접미사 때문에 충돌한 결함을 확인했다. 수리는 archive 전체 파일·디렉터리 경로와 겹치지 않는 독점 생성 staging 공간에서 수행한다. Windows의 최종 rename은 기존 경로가 있으면 실패하며 덮어쓰지 않는다. 기존 추출 파일은 원본 member와 바이트를 비교해 같을 때만 재개하고, 이전 임시 접미사 파일은 그대로 보존한다. 실제 모델·원본 얼굴 자료의 손상 사례가 아니라 제어된 private 반례였으며 초기 검증 실패 원문을 보존한다.

관련 표준 라이브러리의 동작 근거는 Python JSON 직렬화·임시파일 독점 생성·Windows rename 문서다: https://docs.python.org/3.12/library/json.html , https://docs.python.org/3.12/library/tempfile.html , https://docs.python.org/3.12/library/os.html#os.rename .
