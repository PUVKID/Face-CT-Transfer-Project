# 실시간 대시보드 디자인과 구현 기준

이 문서의 실제 API·검사 수·브라우저 확인은 각 추가 기록 당시의 관측입니다. 이후 전체 정렬 결과와 공식 파일 획득은 [최신 기술 보고서](../reports/모델_선정과_현재_진행.md)에 구분해 기록합니다.

화이트·옅은 민트, 큰 현재 작업 제목, 명확한 좌측 탐색과 실제 WebGL 작업 흐름을 사용하는 화면이다. 생성 시안은 비교 자료로만 사용하고 기능 화면의 배경이나 3D 대체 이미지로 넣지 않는다.

## 화면 구조와 토큰

- 바탕은 흰색 `#ffffff`, 좌측 탐색은 옅은 민트 `#f2fbf7`, 3D 영역은 `#eaf9f2`다. 크림색이나 어두운 테마로 바꾸지 않는다.
- 글자는 짙은 남색 `#10212a`, 보조 글자는 `#657b80`, 테두리는 `#dce9e4`, 주 강조는 `#00b580`이다. 카드 반경 20px, 카드 간격 20px, 본문 여백 28px를 사용한다.
- 실제 나눔고딕 Bold 700 파일과 OFL을 패키지에 포함한다. 제목·표·입력·버튼·상태·모바일 글꼴을 일관되게 적용한다. 큰 페이지 제목 36px, 현재 작업 30px, 카드 제목 22px, 본문 14px, 보조 12px를 기준으로 화면 폭에 따라 줄인다.
- 좌측 탐색 폭 224px. 실험 개요·모델·벤치마크·데이터 수집·기법·설정·실행 로그 다섯 항목과 단일 브랜드를 둔다. 선택 시 대응 영역으로 이동하며 좁은 화면에서는 가로 탐색으로 전환한다.
- 상단은 페이지 제목과 실제 갱신 시각·새로고침. 첫 행은 큰 현재 작업·실제 3D 작업 흐름과 우측 모델/원보고/실측 요약이다. 아래는 모델과 측정, 최근 실행 로그이며 이어서 모델·자료·기법·실행 상세를 같은 시각 체계로 제공한다.

## 실제 3D와 상태

Three.js WebGL로 흰색 세라믹 받침·민트 연결부·다운로드/사진/GPU/확대경/보고서 모형을 생성한다. 실제 API 단계 상태를 재질과 상태 문구에 반영한다. 활성 민트·완료 녹색·대기 회색·오류 적색·중단 황색을 구별한다. 클릭 또는 키보드 단계 선택은 세부 정보만 바꾸며 작업을 실행하지 않는다.

기본적으로 작은 회전·팬·활성 펄스만 움직이며 실제 작업 진행률로 해석하지 않는다. 일시정지·재생과 `prefers-reduced-motion`을 지원한다. WebGL 미지원은 명확히 알리고 텍스트 단계 선택을 유지한다. 정지 이미지를 실제 3D처럼 표시하지 않는다.

## API·문구 경계

상대 `GET /api/status`, `GET /api/logs`만 사용한다. 원보고와 직접 측정 탭을 구별하며 IJB-C TAR에는 FAR 조건을 유지한다. LFW는 다른 평가 조건이라고 명시한다. 수치·모델 버전·파일 수신·GPU·로그는 API 값만 표시하고 null은 미측정/미확인, 연결 전은 불러오는 중, API 실패·오래된 상태는 별도 문구로 표시한다. 예시 진행률·성능 곡선·ETA를 생성하지 않는다. 과거 AdaFace의 사용자 중단을 현재 실험과 분리한다.

아이콘은 일정한 1.8px 외곽선 SVG로 구현한다. 조작 요소는 최소 40px, 키보드 초점과 읽기 가능한 상태 문구를 제공한다. 1536×1024 시안을 기준으로 데스크톱과 작은 화면을 확인하고 실제 API 내용 때문에 달라지는 문구·상태·카드 높이는 비교 기록에 남긴다.

## 실제 비교와 행동 검사

2026-11-03 실제 `127.0.0.1:8766` 서버를 CUA Chrome으로 확인했다. 시안과 `design/evidence/live-desktop-final.png`를 같은 검토에서 `view_image`로 직접 비교했다. 검토한 항목은 다음과 같다.

| 비교 지점 | 실제 확인과 차이 |
|---|---|
| 배치 | 민트 좌측 탐색, 큰 작업 카드와 우측 측정 카드, 아래 원보고·로그의 배치를 유지했다. 실제 API의 긴 제목·설명 때문에 높이가 늘어나며 이를 잘라내지 않았다. |
| 글꼴 | 실제 나눔고딕 Bold 파일과 OFL 포함. 브라우저 계산 스타일에서 `Nanum Gothic`, `700`을 확인했다. 시안 이미지의 문자와 픽셀 동일성을 주장하지 않는다. |
| 색·재질 | 흰 바탕·옅은 민트 영역·흰 세라믹 기계·민트 연결관을 구현했다. 실제 오류는 적색, 중단은 황색, 완료는 녹색이며 문구도 함께 표시했다. |
| 3D | 생성 이미지를 넣지 않고 Three.js 실제 캔버스로 구현했다. 일시정지 시 프레임 73이 유지되고 재생 뒤 114로 증가했다. 입체 모형과 아래 단계 버튼으로 세부 내용을 선택한다. |
| 원보고·실측 | IJB-C TAR에는 FAR=1e-4·1e-5를 각각 표시하며 LFW가 다른 조건임을 명시했다. 직접 측정 탭은 실제 빈 결과를 표시했고 원보고를 복사하지 않았다. |
| 조작 | 단계 선택·오류 로그 필터·평가/획득 로그 출처·로그 새로고침·좌측 탐색 이동을 실제로 확인했다. 선택은 작업 실행을 발생시키지 않는다. |
| 상태 문구 | 시안의 준비 문구 대신 실제 IJB 외부 할당량 대기와 stale 경고를 표시했다. 현재 화면의 13.21%는 API의 수신 바이트 진행률이며 얼굴 정확도나 실험 완료율이 아니다. |

직접 관측한 화면 크기는 1664×1132이고 문서 폭은 스크롤바를 제외한 1649px였다. 1536×1024 설정 API는 시간 초과 후 기존 탭 재연결도 실패했고, 새 실제 서버 탭의 DOM·스크린샷은 정상 동작했다. 같은 실패 방법을 반복하거나 다른 브라우저 제어로 우회하지 않았다. 따라서 시안의 정확한 원래 크기 비교·모바일 viewport·모션 축소 환경의 실제 렌더 검사는 미확인이다. 반응형 CSS와 `prefers-reduced-motion` 처리는 구현했지만 해당 환경의 검증 완료로 표현하지 않는다.

소스 밖 `design/evidence/browser-checks.json`에 실제 조작 관측을 보존했다. 초기 설치 설정 실패는 `.npmrc`의 pnpm 11 비인증 설정 미적용이었고 공식 설정 파일로 교체했다. 최종 프로젝트 의존성은 E 프로젝트 cache를 사용하며 ReparsePoint는 0개였다. 초기 인용 명령의 PowerShell 파싱 실패와 제어된 RED는 별도로 보존했고 실패 원문과 수정 전 상태를 보존했다. 로컬 형식 테스트 6개와 Vite production build를 실제 실행했으며 임상 재현 성능·모바일 QA·독립 검증·공개 반영의 완료를 대신하지 않는다.

개발 서버를 정상 종료하며 Three.js 0.187의 `PCFSoftShadowMap` 제거 경고를 새로 관측했다. 설치된 공식 `WebGLShadowMap.js`가 해당 값을 `PCFShadowMap`으로 대체하는 원문을 확인하고, 동일한 실제 렌더 타입을 직접 지정하도록 수정했다. 기존 경고·수정 전 동결 자료는 보존하며 조명·형상·입력·수락 기준은 바꾸지 않았다.

## 느린 로그 응답·프로세스·조작 크기 보완

독립 검토에서 5초 자동 조회가 진행 중인 로그 요청을 취소하여 6~7초 응답이 표시되지 않고 8초 시간 초과도 숨겨지는 경로를 제어 재현했다. 진행 중에는 중복 조회하지 않고 시간 초과 오류를 표시한다. 출처 전환·화면 종료는 요청을 취소하며 늦은 이전 응답을 무시한다. 정상·6.5초 지연·8초 시간 초과와 회복·출처 전환·늦은 응답·종료 취소의 6개 결정적 회귀를 실제 hook 본문에 적용했다. 이전 정상 화면 검사 통과가 이 오류 경로의 검증을 대신하지 않는다.

자원 카드에는 GPU 전체 관측값임을 제목과 설명에 명시하고 API `processes`의 역할·PID·생존 여부·시작 시각만 표시한다. 생존 확인·종료 확인·생존 미확인을 구분하고 배열이 비면 빈 상태를 표시한다. 작업 실행·중단 기능이나 추가 프로세스 정보 노출은 도입하지 않았다. 실제 API의 acquisition 종료 상태와 시작 시각을 브라우저에서 확인했다. 모바일·모션 축소 런타임 검사 한계는 그대로 남는다.

보완 후 형식·프로세스 문구 검사 7개와 로그 hook 회귀 6개, 총 13개를 통과했다. Vite 빌드 종료 코드 0, 본문 빌드 시간 300ms를 관측했다. 실제 데스크톱에서 버튼·select 21개의 폭과 높이를 읽어 모두 40px 이상임을 확인했다. 처음 높이만 고친 뒤 로그 새로고침 폭35px가 남은 실패는 별도로 보존하고 폭40px를 추가했다. 실제 평가 로그의 빈 상태와 획득 로그로의 전환·회복, 프로세스 종료 문구, 3D 캔버스와 브라우저 경고·오류 0건을 확인했다. 이 기록은 구현자 검사이며 별도 독립 검토나 얼굴 성능 측정을 대신하지 않는다.

## 평가조건 미충족과 검출 집계

상태 API의 `evaluation.status=protocol_unmet`를 '평가조건 미충족'으로 표시하고 기존 오류 배지 색과 문구를 함께 사용한다. `detection_coverage`의 유한한 0~1 분율은 100을 곱한 백분율로, `failed_images`의 0 이상 안전 정수는 개수로 표시한다. 누락·null·유효 범위 밖의 값은 미확인이며 0 또는 100으로 만들지 않는다. 정렬 coverage는 얼굴 정확도가 아니라고 명시한다. 평가조건 미충족 또는 검출 실패가 있으면 정확도 미측정·평가 대기 문구를 표시하며 개별 영상 이름이나 특징은 표시하지 않는다.

새 상태·완전/부분/영 coverage·실패 0/양수·미확인 회귀를 추가했다. 기존 느린 로그 회귀 6개를 유지해 전체 Node 검사 16개와 production build를 통과했다. 실제 API는 평가 대기 상태이므로 coverage·검출 실패의 미확인과 원보고/직접 측정 분리를 CUA로 확인했다. 현재 실제 API에 protocol_unmet 사례가 없어 그 상태의 브라우저 렌더는 미검증이며 live 상태에 fixture를 주입하지 않았다. 기존 13개 검사·빌드 통과 이후 별도 통합 검토에서 발견한 누락과 실패 이력은 보존한다. 모바일·모션 축소의 런타임 미검증 한계도 유지한다.

## 처리량 단위 표시

처리량 시계열의 레이블은 실제 `progress.unit`을 따른다. bytes는 '바이트 수신 속도 (바이트/초)', images는 '영상 처리 속도 (영상/초)', 그 외 또는 누락은 '처리 속도 (단위 미확인)'으로 표시한다. GPU 전체 관측 문구는 유지하고 측정값을 새로 만들거나 단위별 수치를 추정하지 않는다. 단위 전환과 미확인 회귀 3개를 추가하며 기존 로그·평가조건·coverage·실패 수 회귀를 유지한다. 단위별 시계열 분리는 상태 생성 코드가 담당하며 프런트 레이블 변경만으로 서로 다른 단위의 과거 값이 정리됐다고 주장하지 않는다. 실제 영상 처리 데이터가 없는 시점에는 해당 경로의 live DOM 검증을 완료로 기록하지 않는다.


추가 데스크톱 관측에서 접근성 트리로 `영상 처리 속도 (영상/초)` 레이블과 실제 처리량 시계열159점을 확인했습니다. 이는 속도 관측의 개수이며 얼굴 정확도가 아닙니다. 이때 저장한 상단 화면 스크린샷에는 하단 속도 레이블이 포함되지 않아 레이블 확인 근거는 접근성 트리 관측과 구분합니다. 이전 문서의 영상 단위 미검증 문구는 당시 관측 범위이며, 모바일·모션 축소 런타임은 계속 미확인입니다.
